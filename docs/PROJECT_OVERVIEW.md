# Spice Express Project Overview

Last reviewed: 2026-05-27

## What This Project Is

Spice Express is a logistics operations web application with a React/Vite frontend and an Express backend. The core product is built around daily transport operations: customers, Lorry Receipts (LRs/AWBs), shipment tracking, invoices, annexures, MIS/customer account views, and business analytics.

The application supports two company identities:

- `11` - Spice Express
- `12` - Asian Trades Link

The frontend is in `frontend/`, and the backend API is in `backend/`.

## Current Architecture

### Frontend

- React 19 with Vite.
- React Router routes inside `frontend/src/PageLayout.tsx`.
- Tailwind CSS, shadcn-style UI primitives, Lucide icons, Framer Motion, and Recharts.
- API wrapper and shared frontend types live in `frontend/src/lib/api.ts`.
- Auth token and user profile are stored in `localStorage`.
- Dark mode is persisted in `localStorage`.

### Backend

- Express 5 API server.
- JWT authentication.
- Security middleware: `helmet`, `cors`, compression, JSON body limits, and auth endpoint rate limiting.
- PDF generation via `jspdf` and `jspdf-autotable`.
- Excel generation via `exceljs`.
- File uploads via `multer`.

### Data Layer

The active repository layer is SQL Server based. Most controllers call repositories under `backend/lib/repositories/`, which query legacy tables such as:

- `dbo.ORDER_HEADER`
- `dbo.ORDER_DELIVERY`
- `dbo.ORDER_TAXES`
- `dbo.INVOICE_HEADER`
- `dbo.INVOICE_DETAIL`
- `dbo.ACCOUNT_MST`
- `dbo.CRDR_ADDINFO`
- `dbo.CRDR_BANKINFO`
- `dbo.CRDR_RATE`
- `dbo.USER_MANAGEMENT`
- `dbo.ROLE_MASTER`

SQL Server connection settings are loaded from environment variables through `backend/lib/sqlServer.js`.

The current operational repositories are SQL Server-first and connect directly to the client's `CMSDB_21052026` database.

## Lane Rates And Default Charges

Lane rates are stored per customer and used during LR creation for TBB/credit shipments.

Built features:

- Add lane rate while creating or editing a customer.
- Rate keys are based on lowercased `from-to` city pairs.
- Supports rate type:
  - per kg
  - per package
- Default customer charges can be stored and reused during LR creation:
  - docket charge
  - door delivery
  - handling
  - pickup
  - transhipment
  - insurance
  - fuel surcharge
  - commission
  - other
  - carrier risk
  - owner risk
  - GST percentage
- LR creation can auto-fill customer default charges.
- LR creation can auto-calculate freight from matching customer lane rates.
- MIS has a Rates tab showing customer lane rates and default charges.

Notes:

- A standalone `RateMapping` page exists in `frontend/src/pages/RateMapping.tsx`, but it is not currently registered as a route in `PageLayout.tsx`.
- Customer rate/default-charge persistence depends on the customer repository mapping to the legacy SQL Server structure.

## Main Data Concepts

### User

Represents an authenticated app user from the legacy user table. Supports role-based access.

Important fields:

- id
- name
- email/username
- role
- company
- phone
- address
- avatar

### Customer

Represents a shipper/client account.

Important fields:

- code
- company/name
- address/state/city/pin
- phone/email
- GSTIN/PAN
- bank details
- lane rates
- default charges

### LR

Represents a shipment/lorry receipt/AWB.

Important fields:

- LR number
- booking date
- status
- company code
- consignor
- consignee
- shipment details
- charges
- customer invoice details
- tracking events

### Invoice

Represents a customer invoice linked to one or more LRs.

Important fields:

- invoice number
- company code
- customer code
- invoice date
- due date
- freight value
- GST
- total amount
- status
- linked LRs

### MIS

Not a separate core table in the live implementation. It is an aggregated view built from customers, LRs, invoices, and customer rates.

## Deployment And Runtime Notes

Frontend:

- Development API: `http://localhost:5000/api`
- Production API fallback: `https://spiceexpress.onrender.com/api`
- Override with `VITE_API_URL`.

Backend:

- Server entry: `backend/server.js`
- Express app: `backend/app.js`
- Health check: `/health`
- SQL Server check script: `npm run db:check` from `backend/`
- Required runtime env includes `JWT_SECRET` and SQL Server variables such as `MSSQL_HOST`, `MSSQL_USER`, and `MSSQL_PASSWORD`.

## Known Implementation Notes

- The active repositories use SQL Server directly.
- The frontend has a `RateMapping` page component, but no route currently exposes it.
- The frontend tracking page currently searches through authenticated LR list data instead of calling the public `/api/lr/track/:id` endpoint directly.
- Some UI text shows mojibake for the rupee symbol in a few TSX files; functionality is separate from that display issue.
- Backend `test` script currently exits with "no test specified".
- Some generated/helper files exist in the root and backend folders, but this overview intentionally documents only the built product surface and the active code paths.
